# 通信诊断日志

应用启动后自动记录，侧边栏底部的「通信日志」提供导出和清空入口。导出调用系统文件选择器，生成按时间顺序合并的 JSONL 文件。日志只存本机，不自动上传。

日志是用户明确要求增加的本地诊断记录，与聊天历史缓存分开；应用不会从日志恢复会话或重新发送消息。

## 记录范围

- 每次 WebSocket 发送和收到的有效协议帧，包括聊天、流式片段、工具、子代理、审批、历史分页、usage 和附件元数据。
- 时间、启动 runId、递增 sequence、连接 ID、地址、发送／接收方向、请求 ID、会话 ID、方法／事件名、消息内容与字符数。
- 发送交给 Socket、网关响应、运行时受理、请求响应耗时、超时、中断、连接状态、解析／处理失败与 SDK 错误码。
- 消息路由和应用到当前会话后的状态。`matched` 只表示仍有等待响应的请求，不表示事件是否属于有效会话；ACK 后的流式事件通常是 false。
- 附件按钮点击及忙碌时忽略、附件操作 ID、HTTP 地址与状态码、接收字节数和耗时、Base64 解码字节数、保存／分享／系统打开及失败原因。

`ws.send.accepted_by_socket` 不等于后端已执行；`request.response_ok` 不等于任务完成；`attachment.system_open.accepted` 只表示系统接受打开请求，不证明外部应用实际显示成功。

## 脱敏与限制

- 保留普通消息正文。常见密钥、密码、Authorization、Cookie、下载令牌和敏感 URL 参数脱敏；Base64 等二进制字段只留长度提示。
- 工具参数或历史消息中的 JSON 字符串也做有限层级的结构化脱敏。不能保证识别自然语言中的所有隐私信息。
- 无法解析的帧记录长度和错误，不落原始文本；过期 Socket 回调只记录丢弃原因与长度。
- 一条记录超过 128 Ki 字符时标记 `truncated`，保存脱敏预览及原长度；这是诊断记录，不是完整抓包。
- 应用私有 `filesDir/diagnostics` 中保存 `communication.jsonl`、`communication.1.jsonl`、`communication.2.jsonl`，每份上限约 4 MiB，最旧文件自动覆盖。
- 异步写入、约 250 ms 合并窗口、2 MiB 待写队列。队列满或写入失败时统计丢弃数量，恢复写入后追加 `log.entries_dropped`；页面也显示计数及文件错误。
- 应用进入后台或退出时尝试刷盘。进程被直接杀死、崩溃或系统 I/O 错误时，末尾待写内容可能丢失。
