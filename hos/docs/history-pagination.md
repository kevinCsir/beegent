# 历史分页兼容

HOS 的 `HistoryClient` 兼容两种 `history.get`：

- 游标协议：`cursor`、`limit`，结束帧含 `has_more`、`next_cursor`、快照字段。
- 页码协议：`page_idx`，结束帧含 `page_idx`、`total_pages`。

`connection.ack.protocol_version` 在已观察的两版服务端均为 `1.0`，不用于判断分页能力。
每条新连接第一次读取历史同时发送 `page_idx: 1`、`cursor: null`、`limit: 50`。
旧服务端读取页码，新服务端优先读取游标。仅在收到合法的历史结束帧后确定协议；
`accepted: true` 不代表已返回历史，也不能用于判断分页协议。

后续请求使用已确认的协议，UI 和消息回放保持共用。`HistoryContinuation` 在内存中
区分服务端游标与本地下一页页码，不把页码伪装成游标。旧协议后续请求完全省略
`cursor`，以免支持两套协议的服务端误选游标分支。断开连接时清空协议识别状态。

两套协议均检查会话、请求标识（服务端提供时）与分页标识。离开会话时丢弃消息，
排空未完成响应后才能重新请求同一会话；等待过程中若断线，旧等待者不得跨连接发送。
历史分片重组、usage 隐藏、快照验证和按时间回放沿用现有机制。

新版保留服务端快照检测；旧版没有同等快照能力，客户端仅能检测总页数变化，
不能保证检测到页数未变的并发历史修改。真实缺失、损坏或页码错误不会被隐藏成空历史。
协议识别和成功页的记录数量会写入已有通信日志。

本次只做源码与编译检查；未运行协议测试、自动测试或真机测试。
